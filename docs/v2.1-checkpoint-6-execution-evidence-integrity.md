**Tanggal:** 5 November 2026. **Status:** `IN_DEVELOPMENT / UNRELEASED`.

**Stable publik tetap v2.0.0. Live GAS staging belum dijalankan (`NOT_RUN`).**

## Tujuan dan akar masalah

Checkpoint 5 sudah mempunyai probe trigger, benchmark 1.200 baris dan linter. Namun status `READY_FOR_OPERATOR_REVIEW` sebelumnya dapat dicapai tanpa bukti bahwa *job utama* pernah diproses oleh continuation trigger, serta tidak memeriksa apakah tiga sampel benchmark membaca SOURCE yang konsisten. Pengecekan terpisah juga belum mewajibkan audit jumlah baris TARGET sama dengan SOURCE/processed/cursor.

Checkpoint 6 memperketat **operational correctness**, bukan AI governance atau rilis/promosi.

`triggerRuns >= 1` **bukan** bukti asal Google. Eksekusi sintetis dalam Node masih dapat menirunya. Untuk live verification, operator wajib memeriksa Google Apps Script **Executions** dan kepemilikan trigger di akun sebenarnya.

## Kontrak penerimaan staging

Sebelum laporan v2 dapat memperoleh status **`READY_FOR_OPERATOR_REVIEW`**, seluruh kondisi berikut harus benar:

1. Preflight `PREFLIGHT_PASS`, SOURCE unik dan minimal 1.200 baris (maksimal 10.000 sesuai batas demo).
2. Job `COMPLETED`, `processed = sourceRows`, `cursor = sourceRows + 2` (header baris 1).
3. `manualRuns >= 1`, `triggerRuns >= 1` pada job utama, dan counter identik dengan laporan trigger ownership.
4. Trigger job memiliki `jobStatus=COMPLETED`, `triggerState=INSPECTED`, `visibleOwnedWakeCount=0`; trigger dengan handler sama milik job lain **tidak dihapus**.
5. Staging probe `OBSERVED`, cleanup UID milik probe selesai (`visibleOwnedCount=0`), timestamp dibuat → teramati → laporan berada dalam urutan yang konsisten.
6. Tiga sampel benchmark SOURCE menghasilkan digest identik (tanpa mengekspor hash), `sourceConsistency=STABLE`, `minMs <= medianMs <= maxMs`.
7. Audit TARGET `COMMITTED_PREFIX_PASS`, `committedRows = matched = sourceRows`, tidak ada missing/mismatch/duplicate, SOURCE seal tetap sama.
8. Hasil lint hanya `READY_FOR_OPERATOR_REVIEW` + `SELF_REPORTED_UNVERIFIED`, tidak pernah otomatis menjadi live PASS.

Pemeriksaan ini adalah *logical cross-check* untuk staging; ia **bukan** verifikasi tanda tangan/identitas Google atau jaminan transaksi atomik saat Sheet diedit manusia. SOURCE wajib dibekukan selama job berlangsung. Benchmark tidak mengukur throughput penulisan TARGET.

## Prosedur operator (project GAS disposable)

1. Buat spreadsheet staging nonproduksi dengan tab `SOURCE` dan `TARGET`, header `record_id | value`. Sediakan sedikitnya 1.200 ID unik; gunakan akun Google khusus yang memasang trigger.
2. Salin **ketiga** `.gs` (file baru Checkpoint 6, jangan mencampur `StagingValidation.gs` CP5 dengan engine CP6). Isi `GAS_RJ_DEMO_SHEET_ID`.
3. Jalankan `preflightReliableSheetUpsert()` dan `startReliableJobsStagingProbe()` secara manual. Sesudah trigger probe teramati, cek `inspectReliableJobsStagingProbe()`.
4. Jalankan `startReliableSheetUpsert()`; **jangan melakukan semua continuation dengan `resumeReliableSheetUpsert()` manual**. Biarkan trigger instalabel menjalankan lanjutan; monitor hingga `COMPLETED`. Pengujian live harus memiliki minimal satu `triggerRuns`.
5. Periksa `inspectReliableSheetUpsertStaging()`, `auditReliableSheetUpsert()` dan Google Apps Script **Executions** untuk melihat UID trigger aktual secara internal, pemilik akun, runtime, dan kegagalan. Jangan mengekspor identifier ke chat/issue.
6. Jalankan `exportReliableJobsStagingEvidenceJson()`, salin laporan yang disanitasi ke `staging-evidence.json` lokal. Verifikasi: `python tools/verify_gas_staging_evidence.py staging-evidence.json`.
7. Jika status `INCOMPLETE_STAGING_EVIDENCE`, lihat daftar `blockers` di JSON verifier dan perbaiki staging. Jika `READY_FOR_OPERATOR_REVIEW`, lakukan review manual dengan metadata Google Executions **secara terpisah**. Linter bukan bukti Google live yang tidak dapat dipalsukan.

## Validasi dan batasan

- Node fakes menguji trigger counter, stale UID, backward-compatible state, SOURCE drift selama benchmark, incomplete evidence, dan mismatch hitungan.
- Python menguji schema v2, tanggal terbalik, NaN/boolean, duplikat key, accidental secrets dan cross-check.
- Seluruh source `.gs` pada contoh dan `skills/01.../examples/reliable-jobs/` wajib byte-identical. Build 16 spesialis dan satu-install v2 tetap valid.
- **Belum diuji di Google Apps Script yang autentik.** Hindari mengklaim telah memvalidasi SLA/jadwal trigger atau performa 1.200 baris pada infrastruktur Google.
