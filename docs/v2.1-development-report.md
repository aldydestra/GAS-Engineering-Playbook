# Laporan Pengembangan GAS Engineering v2.1 — Reliable GAS Jobs

**Checkpoint:** `v2.1.0 / IN_DEVELOPMENT` · **Terakhir stabil:** `v2.0.0` · **Tanggal:** 30 Oktober 2026

## Tujuan dan batas ruang lingkup

Menyediakan starter kerja GAS siap-adaptasi untuk batch yang melebihi batas satu eksekusi. Ini **bukan** perubahan governance AI, bukan migrasi 16 skill menjadi modul besar, dan tidak membuat rilis minor sebelum bukti cukup. Skill publik tetap satu `gas-engineering` dengan 6 family dan 16 spesialis.

## Perubahan teknis rinci

| Area | Sebelum | Pengembangan saat ini | Efek |
|---|---|---|---|
| Resumable jobs | Knowledge/checklist + audit JSON di v1.37 | Starter `.gs` yang mengeksekusi bounded batches dan persistence | Dapat diadaptasi di proyek GAS nyata |
| Checkpoint | Kontrak commit-before-checkpoint tertulis | `processChunk` mengembalikan `committed:true` setelah flush; engine baru memajukan cursor | Crash window aman bila sink idempotent |
| Trigger continuation | Panduan singleton saja | Time-driven one-shot handler + pre-armed watchdog + dedup trigger pemilik | Mengurangi risiko stranded job setelah hard timeout |
| Recovery | Auditor retry/idempotency | Retry hanya error `TRANSIENT`/`RATE_LIMIT`, bounded; status `FAILED` memerlukan reconciliation eksplisit | Hindari infinite retry dan silent progress reset |
| Sheets example | Tidak ada runner praktis | Upsert `record_id`, duplicate-key rejection, batch read, grouped append, `SpreadsheetApp.flush` | Replay tidak melakukan append ganda |
| Skill packaging | Legacy packager tidak membawa asset sumber non-`SKILL.md` | Asset tambahan dicopy byte-identical dan diverifikasi dalam archive final | Contoh `.gs` tersedia melalui satu instalasi |
| CI | Python test + build/verifier GAS | Menambah Node 22 dan fault-injection suite serta asset distribution verification | Regression baru tanpa klaim live API |

## Exit criteria menuju stable v2.1.0

1. Staging Apps Script V8 berhasil memproses dataset multi-batch (lebih dari satu eksekusi), membuktikan trigger continuation dan tidak ada duplicate output.
2. Fault injection aktual terhadap sink/write/checkpoint terobservasi, dan jika ada perbedaan dengan fake maka implementasi disesuaikan.
3. Semua test, source/bundle hashes, routing parity, workflow, dan frozen stable artifact PASS.
4. Runbook operator mencakup permission, trigger ownership, pause/resume, recovery, data snapshot, dan rollback.
5. Versi skill internal serta metadata builder dinaikkan konsisten untuk rilis baru; hanya setelah semua itu hasil dipublikasikan sebagai `v2.1.0`.

## Rollback / migration

Saat ini tidak ada migrasi wajib: proyek yang sudah memasang stable `v2.0.0` tetap menggunakan arsip lama. Untuk uji starter baru, copy `.gs` hanya ke script staging, bukan ke proyek produksi; hentikan dan hapus trigger demo bila tidak diperlukan. Jangan menghapus `releases/v2.0.0`, dan jangan overwrite file rilis lama dengan snapshot development.

## Checkpoint 2 — Trigger ownership & staging safety (30 October 2026)

- `wakeTriggerUid` menjadi metadata checkpoint untuk mengidentifikasi trigger milik job, bukan menghapus semua handler yang sama. Penggantian wake: **create → persist UID → delete old** dengan rollback pada save failure. Masih ada crash window non-atomik yang harus diaudit manual di akun GAS.
- `begin()` sekarang menolak `jobId` yang sudah pernah ada, termasuk `COMPLETED`, agar import baru tidak diam-diam menimpa checkpoint lama.
- Staging preflight **read-only** memeriksa ID ganda/blank di SOURCE/TARGET, termasuk lintas batch, dengan batas 50k baris; ini bukan snapshot isolation.
- Upsert target mengelompokkan contiguous row writes dan membaca kolom key saja. Smoke 1,200 baris di Node fake hanya menunjukkan kontrak logika, **bukan benchmark service calls live**.
- Tambahan test failure window, trigger coexistence, UID persistence rollback, input validation, preflight, batched writes, dan 1,200-row replay.
- Referensi: `docs/v2.1-checkpoint-2-recovery-and-trigger-ownership.md`.
- **Release decision tetap `IN_DEVELOPMENT`**. Skill 01 GAS Core `1.6.0 → 1.6.0 (unreleased content)`, Skill 08 Testing `1.9.0 → 1.9.0 (unreleased content)`. Semua skill lain tidak berubah. Stable archive v2.0.0 tetap immutable.

## Checkpoint 3 — SOURCE drift & reconciliation (2 November 2026)

- Added bounded SHA-256 SOURCE seal on initial start plus per-invocation verification to protect positional cursor against changes *between* runs. Drift pauses job and preserves committed cursor. Does not protect against mid-invocation edits.
- Added read-only committed-prefix reconciliation audit for missing/mismatched/duplicate TARGET keys and preserved source seal; FAILED recovery now requires `true` acknowledgement **and** passing audit.
- Fixed prototype-sensitive key indexes (`Object.create(null)`) and rejected null/invalid record IDs.
- Added simulated fault-injection tests; no live Google staging evidence or GitHub Release. Internal skill versions still unchanged in `Unreleased`.
- Detailed runbook: `docs/v2.1-checkpoint-3-source-seal-reconciliation.md`.


## Checkpoint 4 update — 3 November 2026 (Unreleased)

- **Owned-event fence:** Engine `checkWakeEvent` and `run(...,e)` compare installable `triggerUid` with persisted wake UID, reject foreign/stale events and validate again under `ScriptLock`. Source checks happen only after the early fence.
- **Consistent input within one invocation:** A pinned SHA-256 SOURCE snapshot (up to 10k rows and 2M serialized chars) is captured once, and all batches consume that immutable logical version. It remains a staging starter, not transaction isolation.
- **Observability:** Read-only `inspectReliableSheetUpsertStaging()` reports current-account ownership counts and flags missing-visible-wake; does not infer cross-account trigger inventory.
- **Versioning:** Skills 01, 08, 09 updated in content, but their internal version fields remain unchanged during `Unreleased` development. Stable release v2.0.0 and its checksum are frozen.
- **Staging:** Follow `docs/v2.1-checkpoint-4-trigger-fencing-and-snapshot.md`; live GAS `NOT_RUN` until explicitly executed.
