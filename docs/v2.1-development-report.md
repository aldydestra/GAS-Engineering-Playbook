# Laporan Pengembangan GAS Engineering v2.1 — Reliable GAS Jobs

**Checkpoint:** `v2.1.0 / IN_DEVELOPMENT` · **Terakhir stabil:** `v2.0.0` · **Tanggal:** 30 Oktober 2026

## Tujuan dan batas ruang lingkup

Menyediakan starter kerja GAS siap-adaptasi untuk batch yang melebihi batas satu eksekusi. Ini **bukan** perubahan governance AI, bukan migrasi 16 skill menjadi modul besar, dan tidak membuat rilis minor sebelum bukti cukup. Skill publik tetap satu `gas-engineering` dengan 6 family dan 16 spesialis.

## Perubahan teknis rinci

| Area | Sebelum | Pengembangan saat ini | Efek |
|---|---|---|---|
| Resumable jobs | Knowledge/checklist + audit JSON di v1.37 | Starter `.gs` yang mengeksekusi bounded batches dan persistence | Dapat diadaptasi di proyek GAS nyata |
| Checkpoint | Kontrak commit-before-checkpoint tertulis | `processChunk` mengembalikan `committed:true` setelah flush; engine baru memajukan cursor | Crash window aman bila sink idempotent |
| Trigger continuation | Panduan singleton saja | Time-driven one-shot handler + pre-armed watchdog + dedup trigger pemilik | Mengurangi risiko stranded job setelah hard timeout |
| Recovery | Auditor retry/idempotency | Retry hanya error `TRANSIENT`/`RATE_LIMIT`, bounded; status `FAILED` memerlukan reconciliation eksplisit | Hindari infinite retry dan silent progress reset |
| Sheets example | Tidak ada runner praktis | Upsert `record_id`, duplicate-key rejection, batch read, grouped append, `SpreadsheetApp.flush` | Replay tidak melakukan append ganda |
| Skill packaging | Legacy packager tidak membawa asset sumber non-`SKILL.md` | Asset tambahan dicopy byte-identical dan diverifikasi dalam archive final | Contoh `.gs` tersedia melalui satu instalasi |
| CI | Python test + build/verifier GAS | Menambah Node 22 dan fault-injection suite serta asset distribution verification | Regression baru tanpa klaim live API |

## Exit criteria menuju stable v2.1.0

1. Staging Apps Script V8 berhasil memproses dataset multi-batch (lebih dari satu eksekusi), membuktikan trigger continuation dan tidak ada duplicate output.
2. Fault injection aktual terhadap sink/write/checkpoint terobservasi, dan jika ada perbedaan dengan fake maka implementasi disesuaikan.
3. Semua test, source/bundle hashes, routing parity, workflow, dan frozen stable artifact PASS.
4. Runbook operator mencakup permission, trigger ownership, pause/resume, recovery, data snapshot, dan rollback.
5. Versi skill internal serta metadata builder dinaikkan konsisten untuk rilis baru; hanya setelah semua itu hasil dipublikasikan sebagai `v2.1.0`.

## Rollback / migration

Saat ini tidak ada migrasi wajib: proyek yang sudah memasang stable `v2.0.0` tetap menggunakan arsip lama. Untuk uji starter baru, copy `.gs` hanya ke script staging, bukan ke proyek produksi; hentikan dan hapus trigger demo bila tidak diperlukan. Jangan menghapus `releases/v2.0.0`, dan jangan overwrite file rilis lama dengan snapshot development.
