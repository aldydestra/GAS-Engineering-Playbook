# Reliable GAS Jobs v2.1 — Development Checkpoint 4 Report

**Date:** 3 November 2026  · **Status:** `IN_DEVELOPMENT / Unreleased` · **Last stable:** `v2.0.0`

## Scope and rationale

This checkpoint closes two defects in the Checkpoint 3 demo: a queued *stale or foreign* installable trigger event could use the same handler to start unexpected work, and each chunk inside an execution could read SOURCE independently after an edit. The public `gas-engineering` interface remains one front door / six task families / 16 specialists.

## Implemented changes

| Area | Checkpoint 3 | Checkpoint 4 | Impact |
|---|---|---|---|
| Trigger continuation | Owned trigger cleanup by persisted UID | `e.triggerUid` checked before source access and again under `ScriptLock` | Rejects delayed/foreign events without cursor advance or trigger changes |
| Manual execution | Can directly call runner | Still explicitly supported when no event argument is passed | No migration for manual start/repair |
| SOURCE seal | Verified between invocations, each chunk re-reads SOURCE | Verified *per-invocation in-memory snapshot*, reused across chunks | No within-invocation SOURCE version mixing |
| Snapshot bounds | 10,000 source rows | 10,000 rows + 2,000,000 serialized characters | Prevents unbounded demo workload |
| Staging diagnostics | Inspect status only | `inspectReliableSheetUpsertStaging()` read-only | Shows owned wake visibility per calling account |
| Fault injection | 36 Node cases | 50 Node cases | Covers trigger UID/race and mid-run mutation |

## Remaining risks and next acceptance activity

- Live host may represent `e.triggerUid` differently; unsafe numbers are intentionally rejected. Record actual event type on staging rather than weakening the UID guard.
- User edits to SOURCE after the snapshot capture do not affect the current run, but they invalidate the next-run seal. This is not a Sheets transaction.
- Current-account `getProjectTriggers()` inventory cannot attest to triggers owned by a different account.
- Run disposable staging with >=1,200 records and real time-driven events per `docs/v2.1-checkpoint-4-trigger-fencing-and-snapshot.md`. Keep sanitized results in the provided template.
- **Release decision:** continue `IN_DEVELOPMENT`. No GitHub tag/Release; v2.0.0 remains stable.
