## Mengapa checkpoint ini

## Persiapan wajib di Google Apps Script staging

1. Buat **spreadsheet disposable** khusus pengujian dan project GAS V8 milik satu akun operator; jangan pakai data pelanggan ataupun workbook produksi. Isi dua tab `SOURCE` dan `TARGET`, masing-masing header persis `record_id | value`. Untuk benchmark, siapkan minimal **1.200 `record_id` unik** di SOURCE. TARGET awal boleh hanya header.
2. Salin **tiga file** `.gs` (`ReliableJobs.gs`, `SheetUpsertExample.gs`, `StagingValidation.gs`) ke project itu. Ubah `GAS_RJ_DEMO_SHEET_ID`. Periksa otorisasi Sheets dan `script.scriptapp`; Google menjelaskan installable time-based event membawa `triggerUid`, sedangkan `getProjectTriggers()` hanya terlihat untuk akun pemilik saat ini.
3. Jalankan `preflightReliableSheetUpsert()` **sebelum mengizinkan penulisan**. SOURCE harus dibekukan; SHA-256 seal bukan transaksi yang mengunci edit manusia.
4. Jalankan `startReliableJobsStagingProbe()` secara manual. Ini membuat **satu** one-shot trigger yang memanggil `handleReliableJobsStagingProbe`; tidak membuat trigger job utama, tidak menulis Sheet, dan tidak menyimpan raw UID dalam evidence ekspor. Jalankan `inspectReliableJobsStagingProbe()` setelah trigger benar-benar berjalan. Nilai yang diharapkan: `status=OBSERVED`; jika `WAITING`, cek tab Executions, izin, serta pemilik trigger. Google time-driven `.after(60000)` adalah **minimum delay**, bukan SLA tepat 60 detik.
5. Jalankan `startReliableSheetUpsert()` pada SOURCE disposable yang sudah dibekukan. Periksa `inspectReliableSheetUpsert()` sampai `COMPLETED`. Untuk menguji continuation asli, gunakan batch/`maxBatchesPerRun` yang membutuhkan lebih dari satu eksekusi. Jangan memaksa fungsi `handleReliableJobsStagingProbe({...})` secara manual sebagai bukti live: event sintetis **bisa** meniru UID.
6. Setelah selesai, jalankan `auditReliableSheetUpsert()` dan `collectReliableJobsStagingEvidence()`. Jalankan `exportReliableJobsStagingEvidenceJson()` lalu salin **hanya JSON yang disanitasi** ke file lokal `staging-evidence.json`. Jangan mengekspor log mentah, ID spreadsheet, e-mail, token, source values atau UID trigger.
7. Verifikasi file pada komputer lokal: `python tools/verify_gas_staging_evidence.py staging-evidence.json`. Status `READY_FOR_OPERATOR_REVIEW` berarti *konsisten secara struktur*, **bukan** live PASS terautentikasi. Simpan hasil manual berdasarkan tab Executions sebagai kesaksian operator terpisah, tanpa kredensial atau data sensitif.
8. Bila perlu, jalankan `clearReliableJobsStagingProbe()`. Cleanup tidak pernah menghapus trigger lain yang sekadar memiliki nama handler sama. Jika akun berbeda tidak melihat UID probe `WAITING`, fungsi menolak cleanup dan meminta pemeriksaan owner.

## Batas observabilitas benchmark

- Benchmark **hanya** mengukur panggilan membaca 1.200 baris dan menghitung digest dalam 3 sampel: min, median, max. Ia **tidak** mengukur throughput `setValues()`, latency trigger scheduler, kuota Sheets per hari, atau transaksi yang benar-benar terisolasi.
- Performa tulis harus diperiksa terpisah dari durasi job nyata di Google Executions serta audit TARGET. Tidak ada ambang ms universal; catat runtime dan konsumsi layanan dari project staging bila dapat diobservasi.
- `gasRJReadSourceRows_` tetap memiliki cap 10.000 baris / 2 juta karakter pada contoh dan preflight 50.000 baris. Project besar memerlukan snapshot persistent / indeks stable ID, bukan meningkatkan cap tanpa benchmark.
- ScriptProperties value memiliki batas 9 KB, dan installable triggers 20/pengguna/skrip sesuai kuota resmi saat panduan ditulis; limit dapat berubah. Jangan menyimpan payload data atau log rahasia ke Properties.

**Recovery probe khusus staging:** Bila trigger `WAITING` sudah hilang dari daftar pemilik akibat kegagalan persistence/one-shot, `clearReliableJobsStagingProbe()` sengaja mengembalikan `OWNER_VISIBILITY_CHECK_REQUIRED`. Setelah memeriksa Google Executions dan akun asli pemilik trigger, operator dapat menjalankan `forgetReliableJobsStagingProbeAfterReview(true)` untuk melupakan state probe lama. Fungsi ini tidak menghapus trigger akun lain dan **tidak** dapat dipakai untuk membuktikan bahwa trigger lama telah dihapus di semua akun.
