## Sasaran dan perubahan teknis

Checkpoint 4 hanya menyediakan fakes untuk `triggerUid` dan snapshot; Checkpoint 5 menyediakan jalur pengambilan evidence di **GAS V8 staging nyata**, tetapi belum mengeksekusi akun Google dan tidak pernah melabeli laporan self-reported sebagai live PASS.

1. **Staging Probe:** `StagingValidation.gs` memasang satu clock trigger khusus berdasarkan `getUniqueId()`, mencatat bahwa event telah diterima, dan membersihkan hanya UID miliknya. Event asing/no-UID ditolak. Pembuatan trigger opt-in; akun pemilik berbeda tak dapat diinspeksi lintas akun.
2. **Read-only Diagnostics:** `collectReliableJobsStagingEvidence()` menggabungkan preflight SOURCE/TARGET, job status, audit committed-prefix, trigger ownership, probe status, serta *read-only* benchmark 1.200 baris. Tidak ada data baris, spreadsheet ID, email, token, atau raw trigger UID di report.
3. **Benchmark:** tiga sampel pembacaan SOURCE + SHA-256, melaporkan min/median/max tanpa mengklaim angka throughput TARGET write. Payload benchmark dibatasi 2 juta karakter terserialisasi.
4. **Fail-closed Evidence Lint:** `tools/verify_gas_staging_evidence.py` memeriksa versi schema, konsistensi internal, pengungkapan identifier umum dan *ready-for-review*. Ini **bukan** tanda tangan digital, OAuth audit, atau bukti asal runtime yang tidak dapat dipalsukan.
5. **Reliability:** persistence failure menghapus newly created trigger, lock contention tidak mengubah state, cleanup hanya berdasarkan UID, dan last-resort reset membutuhkan pengakuan eksplisit setelah pemeriksaan owner.
6. **Distribution:** file `StagingValidation.gs` juga disalin byte-identik ke source skill 01, normalized 16-package distribution, dan one-install v2 development bundle.
